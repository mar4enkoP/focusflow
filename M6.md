# Adaptive duration estimates

FocusFlow records elapsed **timer focus**, not verified human activity. No external
service, activity surveillance, or generated historical samples are used.

## Timing and completion

Each task gets a focus session UUID when first started. The original title and
planned duration are captured then. Timestamp differences accumulate independently
of countdown budget; each tick advances the timestamp, so subsequent ticks cannot
count the same interval twice. Pausing and switching settle the interval and remove
its running timestamp. Reset pauses and resets the countdown, preserving measured
work. Extensions change the countdown budget, never the accumulated work.

At zero the countdown still expires without completing the task. Focus measurement
continues, with a status message and the existing pause button available. After
pausing at zero, the same button continues focus. Adding five minutes after expiry
pauses measurement until Start, preserving the existing extension workflow.

Only explicit completion (timer or task list) writes an observation. Unstarted
tasks have no measured observation. Deleting unfinished work discards its session;
deleting completed tasks retains history. Reopening and immediately completing a
task cannot duplicate its observation; starting new work after reopening creates
a new session UUID. Mid-session edits do not rewrite the captured plan/title.

## Reliability

An observation is excluded from learning if any running interval is recovered after
reload, a live update gap exceeds five minutes, the clock moves backward, or total
focus exceeds eight hours. These measurements are retained as uncertain rather
than silently treated as confirmed work. Paused recovery remains reliable. Legacy
sessions are uncertain because their earlier actual focus was never measured.
Intervals under one minute are retained but not used for estimation.

Regular ticks cannot prove attention. The reliability flag means no known timing
anomaly, not guaranteed active work. There is deliberately no confirmation or
analytics dashboard; uncertain observations are simply excluded.

## Deterministic estimate

Match normalized titles using M5's whitespace/case normalization. Use up to nine
most recent reliable completions, restricted to one minute through eight hours.
With fewer than three, return the remembered duration unchanged. With three or four,
blend 50% of their median with 50% of the remembered duration; with five or more,
use 80% median and 20% remembered duration. The median resists isolated outliers.
Round to whole minutes below ten minutes, otherwise five-minute increments, and
clamp to the existing 1–1,440-minute bounds. For example, a 30-minute preference
and 40/45/50-minute completions yield a conservative 40-minute suggestion.

The form shows the estimate and sample count separately from the remembered value.
Only **Use estimate** applies it. Selecting memory still restores title, category
(and its icon), priority and, unless manually edited, preferred duration. Suggestions
never change active tasks or timers. An explicitly saved duration becomes the next
M5 preference as before.

## Persistence

The existing `focusflow` snapshot is version 2 and includes sessions and observations
alongside tasks and countdown state. Version 1 loads without fabricated elapsed
time; the next ordinary save writes version 2. M5's separate storage is unchanged.
Validated records are deduplicated by session UUID. Damaged history preserves the
original stored snapshot, restores valid entries/tasks, and shows the existing
persistence notice; changes then stay in memory for that visit.

Ordinary ticks do not write storage. User actions and countdown expiry save a
snapshot; identical snapshots are skipped. Running timestamps allow elapsed recovery
without periodic writes. As with existing persistence, simultaneous tabs have no
cross-tab conflict resolution. History currently has no automatic retention limit.
