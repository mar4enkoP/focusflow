# Session planning and analytics

## Scheduling

The header opens two compact modal panels, Planner and Analytics. Existing focus,
task ordering, task forms, backdrop geometry and transitions are unchanged.

A proposal uses selected unfinished tasks, a 1–1,440 minute budget, optional breaks
of 0–60 minutes, and a break frequency of 1–20 tasks. A stable greedy algorithm
tries High, Medium, then Low priority; manual list order resolves priority ties.
It never writes to the task order. M6 supplies each forecast when it has sufficient
reliable history; otherwise the task's configured duration is used. Task durations
and countdown budgets are never rewritten by forecasts.

Tasks are indivisible. An oversized task is listed as unscheduled and smaller tasks
can still fit. Breaks are inserted only if the break and following task both fit;
there is no trailing break. This is predictable packing, not a claim of optimal
knapsack utilization. Each selected missing task is explicitly listed as unavailable.

Acceptance persists a reviewed snapshot but never starts a timer. Focus opens the
existing Focus Mode; Start remains explicit. Starting a planned task from ordinary
Focus Mode also associates it with the accepted plan. On completion, navigation
selects the next unfinished planned task without starting it. Manual list order
and non-plan timer navigation remain independent.

## Session window and recalculation

The window begins when the user opens a planned task for focus (or starts it from
Focus Mode). Its wall-clock budget includes breaks, pauses and time away from the
app. Break slots are reminders; there is no second timer or automatic break control.
The user pauses or waits before starting the next task.

Focus accumulated after acceptance is compared against each task's forecast to
detect overruns. Recalculate creates a proposal; it cannot reset a timer or modify
history. It subtracts elapsed wall time, rounds elapsed minutes up conservatively,
retains completed task IDs, and recalculates unfinished work. Active work is first;
its remaining estimate subtracts accumulated focus. An already overrun task gets
an explicit five-minute reserve, never a promise that five minutes will suffice.
If active work cannot fit, other tasks are not scheduled ahead of it. Completed
tasks count toward the break cadence; a break is not inserted before continuing
an active task. Break reservations after recalculation are conservative reminders.

Reject leaves the accepted plan intact. A proposal whose scheduled tasks disappear
or complete, or whose remaining window changes by a minute before acceptance, must
be regenerated. Unstarted plans from another local day require a new proposal to
carry work forward explicitly. Only one accepted session plan is maintained; a new
accepted proposal replaces it. Completed focus history is never replaced.

## Analytics definitions

Only reliable, positive completed observations up to M6's eight-hour safety cap
are included. Session UUIDs deduplicate observations. Unfinished, paused, running,
uncertain and untracked completions are not included in the dashboard totals.
The UI states this scope; the timer alone does not prove attention.

New focus sessions capture their category and contiguous wall-clock intervals.
Adjacent ticks merge into one interval; pauses create gaps. On completion these
intervals are stored with the existing observation. Focus is split at local
midnight using calendar-day arithmetic, including 23/25-hour DST days. The week
starts Monday. Today/week totals and the last seven daily bars sum actual elapsed
milliseconds, not planned time. Completed counts are distinct task IDs (repeated
sessions on a reopened task do not inflate task counts); completion date controls
the today count. Category and planned/actual comparisons cover all recorded time.

Older M6 observations have neither intervals nor categories. Their unlocated time
is attributed to the completion day with an explicit legacy notice; their category
remains Unknown. No historical intervals or categories are invented. Date labels
use the device's current timezone, so changing timezone can change day attribution.

Accuracy is `max(0, 100 × (1 − mean(abs(planned − actual) / actual)))`, using reliable
observations of at least one minute. All eligible samples have equal weight. It is
a descriptive comparison with the originally configured plan, not a measure of
future prediction certainty. Planned/actual rows show the latest ten observations;
the other metrics use all eligible history. Empty history shows zeros and no accuracy.

## Persistence and limits

Optional interval/category fields extend the existing v2 focus snapshot without
invalidating M5/M6 data. Validation rejects overlapping or inflated intervals.
Plans and preferences use an independent versioned `focusflow-plan` key, following
M5's separate-key pattern. Invalid/unsupported plan storage is preserved, with a
notice and in-memory fallback, without blocking task/history persistence. Temporary
invalid form input does not replace saved valid preferences. Proposals and panel
visibility are not persisted; accepted state, selections and break preferences are.
Timer ticks do not write plan storage.

There is no multi-tab conflict resolution, plan archive, automatic breaks, or
automatic task-duration adjustment. Background recovery retains M6's conservative
reliability rules. Planner elapsed time uses the system clock; changing that clock
can alter the remaining session window. Browser visual verification is required
separately when browser tools are available.
